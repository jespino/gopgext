# seg, in Go

A port of PostgreSQL's [`contrib/seg`](https://www.postgresql.org/docs/current/seg.html)
(version 1.4) to Go: the `seg` data type for line segments or
floating-point intervals that keep the significant digits of their bounds
(`'5.0 .. 7.50'`, `'6(+-)0.5'`, `'<1 .. >2e7'`, `'~4.0'`), with its
operators and btree and GiST operator classes, as a drop-in replacement.

Values have upstream's layout (`struct SEG`: 12 bytes passed by
reference: two `float4` bounds, their significant digits and kinds), so
tables and indexes written with the C module work unchanged, and every
function is exported under upstream's C symbol: databases created with
any upstream version (1.1's install script and update scripts included)
work with this library.

| Go source  | Ported from (PostgreSQL 18)                                     |
|------------|-----------------------------------------------------------------|
| `main.go`  | `seg.c`: the type (`//gopgext:type` over `[12]byte`), output, accessors, comparisons, union and intersection |
| `parse.go` | `segscan.l`, `segparse.y` and `seg.c`'s `restore()` and `significant_digits()`: a hand-written scanner and parser with Bison's errors (see contrib/cube's README), and C's `%g`/`%e` formatting |
| `gist.go`  | `seg.c`: `gist_seg_ops` with gopgext/gist (keys are 12-byte segs; split at the median center), exported as `gseg_*` with `//gopgext:alias` |
| `sql/seg.sql` | `seg--1.1.sql` with the 1.2, 1.3 and 1.4 update scripts applied, less the type and its I/O functions (generated by gopgext) |

```sh
gopgext install -version 1.4 -trusted \
    -comment 'data type for representing line segments or floating-point intervals' contrib/seg
```

## gopgext features it brought

- Fixed-size types passed by reference: a `//gopgext:type` over `[N]byte`
  is `CREATE TYPE ... (INTERNALLENGTH = N)`; Go gets a copy of the bytes
  (`fmgr.ArgFixed`, `ReturnFixed`).
- gopgext/gist with fixed-size keys and indexed values (copied to and from
  Go as bytes), and `//gopgext:alias` (see contrib/cube).

## Differences from upstream

- `seg_in` and `seg_out` are created by gopgext with parameter names and
  comments (upstream's have neither).
- GiST page splits sort keys by center with a stable sort (C's `qsort`
  isn't): keys with equal centers may land on other pages (searches find
  the same rows).

## Verification

**Upstream regression tests**: `pg_regress` with `contrib/seg`'s `sql/`,
`expected/` and `data/` unmodified passes against this port: `security`,
`seg` and `partition` on PostgreSQL 18, and `security` and `seg` on
PostgreSQL 14 (REL_14_STABLE's files). `security` creates seg 1.2 and
updates it to 1.3 with upstream's older scripts (installed with the C
module in the test images), on this library.

**Tests**: `test.sql` checks significant digits, `(+-)`, bound kinds, the
12-byte size, errors, and the GiST index (`&&`, `<@`, `<<`) against
sequential scans.

**Differential test**: `differential.sql` declares the original C
library's functions (installed as `seg_c.so`) on the port's type and
compares both on generated input (numbers with 0 to 9 significant digits,
exponents, out-of-range and subnormal values, `<`/`>`/`~` bounds, open
ranges, `(+-)` and `'+-'`, swapped bounds, token soup, trailing garbage and
non-ASCII bytes): parsing (text and exact bounds, or the error's SQLSTATE,
message and detail), output and the other functions on every value and on
pairs, including pairs with equal bounds and different digits or kinds.
With `n=20000`, 0 mismatches on PostgreSQL 18 (20,000 inputs, 7,877
values, 2,283 distinct errors, 4,217,748 pairs per two-argument function)
and 14 (7,929 values, 2,305 errors, 4,193,338 pairs).
